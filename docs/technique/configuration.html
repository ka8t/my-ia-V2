1 Hiérarchie de Configuration

MY-IA utilise une hiérarchie de configuration à 3 niveaux :

Niveau Source Priorité Usage
1 .env Haute Connexion PostgreSQL, identité Docker
2 system_configs (BDD) Moyenne Toute la configuration applicative
3 app/core/config.py Basse Valeurs par défaut si BDD non disponible
Mode recommandé : Avec BOOTSTRAP_FROM_DB=true, seules les variables PostgreSQL sont nécessaires dans .env. Toute autre configuration se fait via l'interface Admin ou directement dans la table system_configs.

2 Variables .env (Obligatoires)

Fichier .env à la racine du projet. Copier depuis .env.example.

2.1 Identité Docker

Variable Description Exemple
SANITIZED_PREFIX Préfixe pour containers et volumes my_ia

2.2 PostgreSQL

Variable Description Exemple
POSTGRES_USER Super-utilisateur PostgreSQL my_ia_postgres_admin
POSTGRES_PASSWORD Mot de passe super-utilisateur MotDePasseSecurise123!
APP_DB_USER Utilisateur applicatif my_ia_db_user
APP_DB_PASSWORD Mot de passe applicatif AutreMotDePasse456!

2.3 Bootstrap

Variable Description Valeur
BOOTSTRAP_FROM_DB Charger la config depuis la BDD au démarrage true (recommandé)

Ces variables ont des valeurs par défaut. Décommenter dans .env uniquement si nécessaire.

3 Configuration BDD (system_configs)

La table system_configs stocke toute la configuration applicative. Elle est accessible via :

  • Interface Admin : Menu Système > Configuration
  • API : GET/PATCH /api/admin/config
  • SQL direct : SELECT * FROM system_configs;

3.1 Catégories de Configuration

Catégorie Description Exemples de clés
app Paramètres application app.name, app.version, app.debug
chat Comportement du chat chat.history_enabled, chat.history_max_turns
rag Recherche documentaire rag.top_k, rag.similarity_threshold, rag.chunk_size
llm Provider LLM llm.provider, llm.ollama.llm_model
ollama Connexion Ollama ollama.host, ollama.port
chroma Connexion ChromaDB chroma.host, chroma.port
storage Stockage fichiers storage.backend, storage.max_file_size_mb
security Sécurité security.jwt_secret_key, security.jwt_expire_minutes
rate_limit Limitation requêtes rate_limit.chat, rate_limit.upload
email Envoi emails email.backend, email.smtp_host
registration Inscription registration.require_approval, registration.allowed_domains
speech Reconnaissance vocale speech.enabled, speech.auto_send
sources Sources RAG sources.max_context_items, sources.cache_ttl
debug Mode debug debug.endpoints_enabled, debug.verbose_logging
deploy Déploiement deploy.remote_host, deploy.git_branch

3.2 Types de Valeurs

Type Format Exemple
string Texte "mistral"

Clé Type Défaut Description

4 Valeurs par Défaut (config.py)

Le fichier app/core/config.py définit les valeurs par défaut utilisées si :

  • La BDD n'est pas accessible au démarrage
  • Une clé n'existe pas dans system_configs
Important : Ces valeurs sont des fallbacks. En production, toute la configuration doit être dans la BDD.

5 Ordre de Résolution

Quand l'application demande une configuration :

  1. Variables d'environnement (priorité maximale pour DATABASE_URL, BOOTSTRAP_FROM_DB)
  2. Table system_configs (si BOOTSTRAP_FROM_DB=true)
  3. Valeurs par défaut config.py (fallback)
# Exemple de résolution pour "rag.top_k"

1. os.getenv("RAG_TOP_K") ?
   -> Non défini dans .env

2. system_configs WHERE key = "rag.top_k" ?
   -> Trouvé: value = "15"
   -> Utilisé: 15

3. settings.top_k (config.py) ?
   -> Non atteint car trouvé en BDD

6 Modifier la Configuration

6.1 Via Interface Admin (Recommandé)

  1. Connexion : https://localhost:8081
  2. Menu : Système > Configuration
  3. Modifier les valeurs
  4. Sauvegarder

6.2 Via API

# Lire une config
curl -X GET "http://localhost:8080/api/admin/config/rag.top_k" \
  -H "Authorization: Bearer $TOKEN"

# Modifier une config
curl -X PATCH "http://localhost:8080/api/admin/config/rag.top_k" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"value": "20"}'

6.3 Via SQL Direct

-- Lire
SELECT * FROM system_configs WHERE key = 'rag.top_k';

-- Modifier
UPDATE system_configs SET value = '20' WHERE key = 'rag.top_k';

-- Ajouter
INSERT INTO system_configs (key, value, value_type, category, description)
VALUES ('custom.my_key', 'my_value', 'string', 'custom', 'Ma config personnalisée');

7 Redémarrage Requis

Certaines configurations nécessitent un redémarrage :

Configuration Redémarrage Raison
Connexions (ollama, chroma, whisper) Oui Clients initialisés au démarrage
Security (JWT, secrets) Oui Clés chargées au démarrage
RAG (top_k, threshold) Non Lus dynamiquement
Chat (history, summary) Non Lus dynamiquement
Storage (quotas, types) Non Lus dynamiquement

8 Troubleshooting

La configuration ne se charge pas depuis la BDD

  • Vérifier BOOTSTRAP_FROM_DB=true dans .env
  • Vérifier que PostgreSQL est accessible
  • Consulter les logs : docker logs my_ia_app | grep -i bootstrap

Une valeur ne prend pas effet

  • Vérifier le type de la valeur (string vs int)
  • Redémarrer si nécessaire : docker restart my_ia_app
  • Vérifier qu'il n'y a pas de variable d'environnement qui override
