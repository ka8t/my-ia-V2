2. Installation

Étape 1 : Préparation du serveur

# Mise à jour système
sudo apt update && sudo apt upgrade -y

# Installation des dépendances
sudo apt install -y curl git ca-certificates gnupg

# Installation Docker (script officiel)
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

# Redémarrer la session pour appliquer le groupe docker
exit

Étape 2 : Installation du driver NVIDIA (si GPU)

# Ubuntu 22.04 avec GPU NVIDIA
sudo apt install -y nvidia-driver-535 nvidia-container-toolkit

# Vérifier l'installation
nvidia-smi

# Configurer Docker pour GPU
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

Étape 3 : Déploiement MY-IA

# Cloner le projet
git clone https://github.com/votre-org/my-ia.git /opt/my-ia
cd /opt/my-ia

# Configuration initiale
cp env.template .env
nano .env  # Configurer les variables (voir section Configuration)

# Démarrer l'application
./scripts/start.sh

# Vérifier que tous les containers tournent
docker compose ps

Étape 4 : Vérification

# Vérifier la santé de l'API
curl http://localhost:8080/api/health

# Réponse attendue
{"status": "healthy", "llm": {"provider": "ollama", "model": "mistral"}, "chroma": true}
✅ Succès : L'application est accessible sur http://votre-serveur:3000 (utilisateurs) et :8081 (admin).

Configuration de sécurité

⚠️ Obligatoire en production :
  • Changer tous les mots de passe par défaut
  • Configurer une SECRET_KEY unique (64 caractères aléatoires)
  • Activer HTTPS avec certificats SSL valides
  • Configurer ALLOWED_HOSTS avec votre domaine
  • Activer le firewall (ufw ou iptables)
  • Configurer les sauvegardes automatiques
  • Optionnel : activer le rate limiting
  • Optionnel : configurer les webhooks d'alerte

Configuration du firewall

# Activer ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Autoriser SSH
sudo ufw allow ssh

# Autoriser HTTP/HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Activer le firewall
sudo ufw enable
sudo ufw status

4. SSL & Reverse proxy

Option 1 : Let's Encrypt (gratuit)

# Installer Certbot
sudo apt install certbot

# Générer les certificats (arrêter le serveur web d'abord)
sudo certbot certonly --standalone -d myia.entreprise.com

# Copier vers MY-IA
sudo cp /etc/letsencrypt/live/myia.entreprise.com/fullchain.pem /opt/my-ia/ssl/
sudo cp /etc/letsencrypt/live/myia.entreprise.com/privkey.pem /opt/my-ia/ssl/
sudo chown -R $(whoami):$(whoami) /opt/my-ia/ssl/

# Configurer le renouvellement automatique
sudo certbot renew --dry-run

Option 2 : Certificat entreprise

# Copier vos certificats
cp /path/to/certificate.crt /opt/my-ia/ssl/fullchain.pem
cp /path/to/private.key /opt/my-ia/ssl/privkey.pem

# Vérifier les permissions
chmod 600 /opt/my-ia/ssl/privkey.pem

Configuration Nginx (reverse proxy externe)

Si vous utilisez un Nginx externe comme reverse proxy :

# /etc/nginx/sites-available/myia
server {
    listen 80;
    server_name myia.entreprise.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name myia.entreprise.com;

    ssl_certificate /etc/letsencrypt/live/myia.entreprise.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/myia.entreprise.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # Interface utilisateurs
    location / {
        proxy_pass https://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # API
    location /api/ {
        proxy_pass http://localhost:8080/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

# Interface admin (sous-domaine séparé)
server {
    listen 443 ssl http2;
    server_name admin.myia.entreprise.com;

    ssl_certificate /etc/letsencrypt/live/myia.entreprise.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/myia.entreprise.com/privkey.pem;

    # Restreindre l'accès par IP (optionnel)
    # allow 192.168.1.0/24;
    # deny all;

    location / {
        proxy_pass https://localhost:8081;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
# Activer le site et recharger
sudo ln -s /etc/nginx/sites-available/myia /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

Logs

# Voir les logs en temps réel
docker compose logs -f app

# Logs d'un service spécifique
docker compose logs -f postgres
docker compose logs -f chroma

# Logs avec horodatage et limite
docker compose logs --since 1h --timestamps app

Alertes recommandées

  • Health check échoué — /api/health retourne autre chose que "healthy"
  • Latence élevée — Temps de réponse > 5s
  • Espace disque — < 20% disponible
  • Mémoire — Utilisation > 90%
  • Erreurs 5xx — Taux > 1%

6. Sauvegardes

Éléments à sauvegarder

ComposantEmplacementPriorité
Base PostgreSQLVolume postgres_dataCritique
Base ChromaDBVolume chroma_dataCritique
Documents uploadés/opt/my-ia/storage/Important
Configuration/opt/my-ia/.envImportant
Certificats SSL/opt/my-ia/ssl/Normal

Sauvegarde manuelle

# Arrêter les services (optionnel mais recommandé)
./scripts/stop.sh

# Sauvegarder PostgreSQL
docker compose exec postgres pg_dump -U myia_user myia_db > backup_$(date +%Y%m%d).sql

# Sauvegarder les volumes
docker run --rm \
  -v myia_postgres_data:/data \
  -v $(pwd)/backups:/backup \
  alpine tar czf /backup/postgres_$(date +%Y%m%d).tar.gz /data

docker run --rm \
  -v myia_chroma_data:/data \
  -v $(pwd)/backups:/backup \
  alpine tar czf /backup/chroma_$(date +%Y%m%d).tar.gz /data

# Sauvegarder les fichiers
tar czf backups/storage_$(date +%Y%m%d).tar.gz storage/
cp .env backups/env_$(date +%Y%m%d).bak

# Redémarrer
./scripts/start.sh

Sauvegarde automatique (cron)

# Créer le script de sauvegarde
cat > /opt/my-ia/scripts/backup-cron.sh << 'EOF'
#!/bin/bash
cd /opt/my-ia
DATE=$(date +%Y%m%d_%H%M)
BACKUP_DIR=/opt/my-ia/backups

# PostgreSQL
docker compose exec -T postgres pg_dump -U myia_user myia_db | gzip > $BACKUP_DIR/db_$DATE.sql.gz

# Rotation (garder 7 jours)
find $BACKUP_DIR -name "db_*.sql.gz" -mtime +7 -delete

# Optionnel : envoyer vers stockage distant (S3, rsync, etc.)
# aws s3 cp $BACKUP_DIR/db_$DATE.sql.gz s3://bucket/backups/
EOF

chmod +x /opt/my-ia/scripts/backup-cron.sh

# Ajouter au crontab (sauvegarde quotidienne à 2h)
(crontab -l 2>/dev/null; echo "0 2 * * * /opt/my-ia/scripts/backup-cron.sh >> /var/log/myia-backup.log 2>&1") | crontab -

Restauration

# Restaurer PostgreSQL
gunzip -c backups/db_20240115.sql.gz | docker compose exec -T postgres psql -U myia_user myia_db

# Restaurer un volume
docker run --rm \
  -v myia_postgres_data:/data \
  -v $(pwd)/backups:/backup \
  alpine sh -c "cd /data && tar xzf /backup/postgres_20240115.tar.gz --strip-components=1"

7. Mises à jour

Procédure standard

1. Sauvegarder
Exécuter le script de sauvegarde
2. Arrêter l'application
./scripts/stop.sh
3. Récupérer la nouvelle version
git pull origin main
4. Rebuild si nécessaire
docker compose build (si requirements changés)
5. Redémarrer
./scripts/start.sh
6. Vérifier
curl https://myia.entreprise.com/api/health

Script de déploiement

# Utiliser le script de déploiement intégré
./scripts/deploy.sh remote

# Le script effectue automatiquement :
# 1. Push git vers origin
# 2. SSH vers le serveur
# 3. git pull sur le serveur
# 4. Restart des containers
# 5. Vérification health check

Rollback

# En cas de problème, revenir à la version précédente
git log --oneline -5  # Trouver le commit précédent
git checkout <commit-hash>
./scripts/start.sh
✅ Zero downtime : Pour les mises à jour sans interruption, utilisez un load balancer avec deux instances en rolling update.

8. Dépannage

Problèmes courants

SymptômeCause probableSolution
Container ne démarre pas Port déjà utilisé docker compose logs app puis libérer le port
Erreur "Connection refused" Service non démarré Vérifier docker compose ps
Réponses LLM très lentes Pas de GPU / modèle trop gros Vérifier nvidia-smi, réduire la taille du modèle
Erreur "Out of memory" RAM insuffisante Augmenter la RAM ou réduire la taille des modèles
Erreur SSL "certificate expired" Certificat non renouvelé sudo certbot renew
Login échoue Pool SQLAlchemy caché docker restart myia_app

Commandes de diagnostic

# État des containers
docker compose ps

# Utilisation des ressources
docker stats

# Espace disque des volumes
docker system df -v

# Logs avec filtrage
docker compose logs --since 30m app | grep -i error

# Connexion à PostgreSQL
docker compose exec postgres psql -U myia_user myia_db

# Test de l'API
curl -s http://localhost:8080/api/health | jq .

Réinitialisation complète

⚠️ Attention : Cette procédure supprime toutes les données. À utiliser uniquement en dernier recours. 
# Arrêter et supprimer tout
./scripts/stop.sh --volumes

# Supprimer les images
docker compose down --rmi all

# Réinstaller
./scripts/start.sh
