1. Branding & apparence

La personnalisation du branding se fait entièrement via l'interface admin, sans toucher au code.

Configuration via l'admin

Accédez à Configuration > Général pour modifier :

ParamètreDescriptionRecommandation
Nom de l'applicationAffiché dans l'en-tête et le titreNom court et mémorable
Logo principalEn-tête de l'applicationPNG/SVG transparent, 200x50px
FaviconIcône du navigateurICO/PNG carré, 32x32 ou 64x64
DescriptionSous-titre de la page de connexion1-2 phrases descriptives

Personnalisation des textes

Les textes de l'interface sont personnalisables via les fichiers de traduction :

UI-SHARED/locales/
├── fr.json    # Français
└── en.json    # Anglais

Pour personnaliser un texte, modifiez la clé correspondante :

// fr.json
{
  "app_welcome_title": "Bienvenue chez Acme Corp",
  "app_welcome_subtitle": "Votre assistant intelligent",
  "chat_placeholder": "Comment puis-je vous aider ?"
}
💡 Conseil : Créez une copie des fichiers de traduction et adaptez les clés à votre client.

2. Thème personnalisé

Le thème visuel est défini par des variables CSS dans UI-SHARED/css/base/variables.css.

Palette de couleurs

/* UI-SHARED/css/base/variables.css */
:root {
  /* Couleurs principales */
  --primary: #1e3a5f;           /* Bleu foncé */
  --primary-light: #2d5a8e;     /* Bleu clair */
  --primary-dark: #152a45;      /* Bleu très foncé */

  /* Couleur d'accent */
  --accent: #0d9488;            /* Turquoise */
  --accent-light: #14b8a6;
  --accent-dark: #0a7570;

  /* Arrière-plans */
  --bg-primary: #ffffff;
  --bg-secondary: #f8fafc;
  --bg-tertiary: #f1f5f9;

  /* Texte */
  --text-primary: #1e293b;
  --text-secondary: #64748b;
  --text-muted: #94a3b8;

  /* États */
  --success: #10b981;
  --warning: #f59e0b;
  --danger: #ef4444;
  --info: #3b82f6;
}

Adaptation pour un client

Pour appliquer la charte graphique d'un client :

1. Récupérer la charte graphique
Couleur principale, couleur secondaire, police de caractères
2. Modifier les variables CSS
Remplacer les valeurs dans variables.css
3. Télécharger le logo
Via l'interface admin (Configuration > Général)
4. Valider visuellement
Vérifier le rendu en mode clair et sombre

Mode sombre

Le mode sombre est supporté nativement. Les variables sont surchargées automatiquement :

/* Mode sombre */
[data-theme="dark"] {
  --bg-primary: #0f172a;
  --bg-secondary: #1e293b;
  --text-primary: #f1f5f9;
  --text-secondary: #94a3b8;
}
✅ Les utilisateurs peuvent choisir leur thème (clair/sombre/système) dans leurs préférences.

3. Comportement de l'IA

Le comportement de l'IA est entièrement configurable via l'interface admin.

Prompt système global

Accédez à Configuration > Chat pour définir le prompt système par défaut :

Tu es un assistant professionnel pour [Nom Entreprise].

Règles de comportement :
- Tu réponds toujours en français.
- Tu cites tes sources quand tu utilises des documents.
- Tu restes professionnel et courtois.
- Si tu ne connais pas la réponse, dis-le clairement.
- Tu ne donnes jamais d'informations confidentielles.

Contexte entreprise :
[Description de l'entreprise, secteur d'activité, informations clés]

Paramètres du modèle LLM

ParamètrePlageEffetRecommandation
Température0.0 – 1.0Créativité des réponses0.3 (factuel) – 0.7 (créatif)
Top P0.0 – 1.0Diversité du vocabulaire0.9 (recommandé)
Max tokens100 – 4096Longueur max des réponses1024 (détaillé), 512 (concis)

Paramètres RAG

ParamètreDéfautDescription
Top K5Nombre de passages remontés par recherche
Seuil de similarité0.7Score minimum pour inclure un passage
Inclure sourcesOuiAfficher les documents cités
⚠️ Attention : Un Top K trop élevé peut diluer le contexte et dégrader la qualité des réponses.

4. Modes de conversation

Les modes de conversation permettent de créer des assistants spécialisés avec des comportements différents.

Cas d'usage

💼 Mode RH
Prompt : "Tu es un expert RH..."
Collections : Documents RH, procédures
Température : 0.3 (précis)
📊 Mode Commercial
Prompt : "Tu aides les commerciaux..."
Collections : Catalogues, tarifs, CRM
Température : 0.5 (équilibré)
⚙️ Mode Technique
Prompt : "Tu es un expert technique..."
Collections : Documentation, specs
Température : 0.2 (très précis)
🎓 Mode Formation
Prompt : "Tu es un formateur..."
Collections : Supports, tutoriels
Température : 0.6 (pédagogique)

Création via l'admin

Dans Configuration > Modes de conversation :

1. Nom et description
Identifiant clair pour les utilisateurs
2. Prompt spécifique
Instructions de comportement pour ce mode
3. Collections associées
Sélectionner les sources de données pertinentes
4. Paramètres LLM
Température, max tokens, etc.

Création via l'API

POST /api/admin/modes
{
  "name": "mode-technique",
  "display_name": "Assistant Technique",
  "description": "Pour les questions techniques",
  "system_prompt": "Tu es un expert technique...",
  "temperature": 0.2,
  "max_tokens": 2048,
  "collection_ids": ["uuid1", "uuid2"],
  "is_default": false
}

5. Sources de données

MY-IA peut intégrer des sources de données externes en plus des documents uploadés.

Types de sources

TypeUsageConfiguration
Site webIndexer un site completURL racine, profondeur de crawl, filtres
API RESTDonnées dynamiquesURL endpoint, headers d'auth, mapping
Base SQLInterroger une BDDConnection string, requêtes SQL
RSS/AtomFlux d'actualitésURL du flux, fréquence de refresh

Configuration d'un crawl web

Via l'admin (Gestion > Sources) :

{
  "type": "web",
  "url": "https://docs.entreprise.com",
  "config": {
    "max_depth": 3,
    "include_patterns": ["/docs/*", "/faq/*"],
    "exclude_patterns": ["/api/*", "/admin/*"],
    "respect_robots_txt": true,
    "rate_limit_ms": 500
  }
}

Créer un connecteur personnalisé

Pour ajouter un nouveau type de source, implémentez l'interface de base :

# app/features/sources/connectors/custom.py
from app.features.sources.connectors.base import BaseConnector

class CustomConnector(BaseConnector):
    """Connecteur personnalisé pour [service]."""

    async def fetch_content(self) -> list[dict]:
        """Récupère le contenu de la source."""
        # Votre logique de récupération
        return [
            {"content": "...", "metadata": {"url": "..."}}
        ]

    async def validate_config(self) -> bool:
        """Valide la configuration du connecteur."""
        # Vérifier les paramètres requis
        return True

    async def test_connection(self) -> dict:
        """Teste la connexion à la source."""
        return {"status": "ok", "message": "Connecté"}
💡 Indexation : Les sources sont ré-indexées selon la fréquence configurée (quotidien, hebdomadaire, etc.).

6. Intégrations

Webhooks

MY-IA peut notifier des systèmes externes via webhooks :

  • Nouvelle conversation — Déclenché quand un utilisateur démarre un chat
  • Document uploadé — Quand un document est ajouté et indexé
  • Utilisateur créé — Inscription d'un nouvel utilisateur
  • Erreur système — Pour alerter en cas de problème

SSO / SAML

Intégrez l'authentification de votre client (Azure AD, Okta, Google, etc.) :

# Configuration OAuth2 dans .env
OAUTH_PROVIDER=azure
OAUTH_CLIENT_ID=your-client-id
OAUTH_CLIENT_SECRET=your-secret
OAUTH_TENANT_ID=your-tenant-id
OAUTH_REDIRECT_URI=https://myia.client.com/auth/callback

Embed dans une application

Intégrez MY-IA dans une application existante :

Option 1 : iframe

<iframe
  src="https://myia.client.com/embed/chat"
  width="400"
  height="600"
  frameborder="0"
></iframe>

Option 2 : Widget JS

<script src="https://myia.client.com/widget.js"></script>
<script>
  MyIA.init({
    apiUrl: 'https://myia.client.com/api',
    token: 'user-token'
  });
</script>

Intégration MCP

MY-IA supporte le protocole Model Context Protocol pour s'intégrer avec des outils AI :

# Configuration MCP server
{
  "mcpServers": {
    "myia": {
      "command": "myia-mcp-server",
      "args": ["--api-url", "https://myia.client.com/api"]
    }
  }
}

MY-IA supporte plusieurs langues avec un système de traduction simple.

Langues disponibles

Ajouter une nouvelle langue

1. Copier le fichier de référence

2. Traduire toutes les clés
Conserver la structure, traduire les valeurs
3. Enregistrer la langue
Ajouter dans UI-SHARED/js/services/i18n.js
4. Tester
Vérifier toutes les pages et fonctionnalités

// locales/fr.json
{

8. Déploiement multi-client

Deux approches pour déployer MY-IA pour plusieurs clients :

Option 1 : Instances séparées

  • Isolation complète des données
  • Personnalisation totale par client
  • Performances garanties
  • Mises à jour indépendantes
  • Coût infrastructure plus élevé
  • Maintenance multiple

Option 2 : Multi-tenant

  • Mutualisation des ressources
  • Maintenance centralisée
  • Coût réduit
  • Isolation logique (tenant_id)
  • Personnalisation limitée
  • Risque de noisy neighbor

Recommandations

ScénarioApprocheJustification
Grands comptes (>100 users)Instance dédiéePerformances et sécurité
PME (10-100 users)Instance dédiéeIsolation des données
Démo / POCMulti-tenantCoût réduit
SaaS grand publicMulti-tenantScalabilité
💡 Architecture multi-tenant : Les données sont séparées par tenant_id dans PostgreSQL et par préfixe dans ChromaDB.
