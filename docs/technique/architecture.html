1. Vue d'ensemble

MY-IA est une application RAG (Retrieval-Augmented Generation) complète, conçue pour être déployée on-premise. Elle combine un LLM local avec une base de documents vectorisée pour fournir des réponses contextualisées.

Principes clés

🏠 On-premise
Données et modèles restent sur votre infrastructure. Aucune fuite vers le cloud.
🔄 Modulaire
Chaque composant peut être remplacé ou étendu indépendamment.
🚀 Scalable
Architecture container qui s'adapte de 10 à 10 000 utilisateurs.
🔒 Sécurisé
Authentification JWT, chiffrement, audit complet des actions.

Principes de développement

🚫 Pas de HTML inline
Tout le HTML dynamique passe par Templates.* ou templates externes.
🚫 Pas de CSS inline
Utiliser les classes CSS du design system, jamais style="...".
🔄 Code partagé
Tout code commun va dans UI-SHARED/, jamais de duplication.
🌍 i18n obligatoire
Toutes les chaînes via t('cle'), pas de texte hardcodé.

6. Pipeline RAG

Le processus complet de réponse à une question :

1. Réception de la question
L'utilisateur envoie un message via POST /api/chat/stream
2. Vérification du contexte
Détermination de la collection et du corpus associé
3. Génération des embeddings
La question est transformée en vecteur via le modèle d'embeddings (nomic-embed-text)
4. Recherche vectorielle
ChromaDB trouve les top_k passages les plus similaires (cosine similarity)
5. Recherche multi-collection (si corpus)
Si la collection a un corpus, recherche dans toutes les collections du corpus
6. Construction du prompt
Injection du contexte trouvé + historique conversation + prompt système
7. Génération streamée
Le LLM génère la réponse token par token via SSE

Mesures de sécurité

  • Mots de passe hashés avec bcrypt (via pwdlib)
  • Tokens JWT avec expiration configurable
  • HTTPS obligatoire en production (certificats SSL)
  • Rate limiting par IP (SlowAPI)
  • CORS configurable (origines autorisées)
  • Audit log de toutes les actions sensibles
  • Validation Pydantic sur toutes les entrées
  • Prévention injection SQL (SQLAlchemy ORM)
