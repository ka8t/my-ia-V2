1 Vue d'Ensemble

MY-IA V2 est une stack 100% Python : un seul container app sert à la fois le HTML (Jinja2) et l'API JSON (/api/v1/*). Les anciens containers UI-FRONT / UI-BACK de la stack JS V1 ont disparu.

6 Sécurité & Chiffrement

Chiffrement PII (AES-256-GCM)

# app/common/crypto/encryption.py

class EncryptionService:
    """
    Chiffrement AES-256-GCM pour données personnelles.
    - IV aléatoire unique par opération (12 bytes)
    - Tag d'authentification (16 bytes)
    - Format stocké: IV || Ciphertext || Tag (base64)
    """

    def encrypt(self, plaintext: str) -> str:
        iv = os.urandom(12)  # Nonce unique
        cipher = Cipher(
            algorithms.AES(self.key),
            modes.GCM(iv),
            backend=default_backend()
        )
        encryptor = cipher.encryptor()
        ciphertext = encryptor.update(plaintext.encode()) + encryptor.finalize()
        return base64.b64encode(iv + ciphertext + encryptor.tag).decode()

Données chiffrées : Prénom / Nom, Téléphone, Adresse, Autres PII configurables

Configuration SSL

Le projet supporte deux modes SSL :

Option 1 : Certificats self-signed (sans domaine)

Configuration par défaut pour les déploiements sans nom de domaine. Affiche un avertissement dans le navigateur mais le trafic est chiffré.

# Générer les certificats self-signed sur le VPS
cd /home/debian/my-ia
mkdir -p ssl
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout ssl/selfsigned.key \
  -out ssl/selfsigned.crt \
  -subj "/CN=my-ia.local/O=MY-IA/C=FR"

# Redémarrer les containers UI
docker compose restart ui-front ui-back

Fichiers impliqués :

  • ssl/selfsigned.crt et ssl/selfsigned.key — Certificats
  • docker/nginx/ssl-proxy.conf — Config nginx pour ui-front
  • docker/nginx/ssl-back-proxy.conf — Config nginx pour ui-back
  • docker-compose.ssl.yml — Override Docker pour activer SSL

Option 2 : Let's Encrypt (avec domaine)

Configuration recommandée pour la production avec un nom de domaine. Certificat gratuit et reconnu par les navigateurs.

# 1. Installer nginx et certbot sur le VPS
sudo apt install nginx certbot python3-certbot-nginx

# 2. Obtenir le certificat Let's Encrypt
sudo certbot --nginx -d votre-domaine.com

# 3. Copier la config reverse proxy
# (remplacer les variables ${...} par les vraies valeurs)
sudo cp nginx/prod.conf /etc/nginx/sites-available/myia
sudo ln -s /etc/nginx/sites-available/myia /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 4. Configurer les containers en HTTP simple (plus besoin de SSL interne)
# Modifier docker-compose pour exposer les ports HTTP uniquement

Déploiement distant

# Déployer sur le VPS (depuis la branche main)
./scripts/deploy.sh remote

# Le script effectue :
# 1. Vérifie qu'on est sur la branche main
# 2. Vérifie qu'il n'y a pas de modifications non commitées
# 3. Push vers origin
# 4. git fetch + reset --hard sur le VPS
# 5. Nettoyage des fichiers inutiles (docs, tests, etc.)
# 6. Rebuild + restart des containers
# 7. Migrations Alembic
# 8. Health check

Fichiers conservés sur le VPS (non supprimés par le déploiement) :

  • ssl/ — Certificats SSL
  • nginx/ — Config nginx système
  • docker-compose.ssl.yml — Override SSL
  • .env — Configuration locale

Fichiers supprimés après déploiement (inutiles en prod) :

  • docs/, tests/ — Documentation et tests
  • CLAUDE.md, pytest.ini — Dev tools
  • static-datas/ — Données d'import initial
  • docker-compose.dev.yml, docker-compose.staging.yml — Overrides non-prod
