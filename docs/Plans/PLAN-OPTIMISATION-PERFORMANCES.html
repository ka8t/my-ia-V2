Objectifs de latence (P95) :
  • TTFT : 300-800 ms
  • Réponse complète : 1-3 s pour 2-4 paragraphes
  • Retrieval : < 120-150 ms
Contraintes d'architecture — TOUJOURS respecter :
  • Corpus = Documents + Sources. Toute optimisation doit s'appliquer aux DEUX types de contenu.
  • Provider = Les collections ChromaDB sont suffixées par provider (*_ollama, *_llamacpp). Les embeddings sont INCOMPATIBLES entre providers.
  • Multi-collections = Un corpus peut avoir plusieurs collections. La recherche RAG utilise _search_with_corpus_fallback().
  • Métadonnées = Chaque chunk a corpus_id, document_id, source_id, provider.

Voir : Documentation Collections | Section 8 : Corpus & Multi-Providers

⚠️ Pas de valeurs en dur — Configuration 100% en BDD :
  • Toute valeur configurable doit provenir de la table system_configs PostgreSQL.
  • Jamais de constantes hardcodées : TTL, tailles de cache, seuils, timeouts, etc. → BDD.
  • Utiliser SystemConfigService.get() avec une clé préfixée (ex: perf.cache_ttl, perf.embedding_cache_size).
  • Valeurs par défaut : définies dans app/core/config.py via settings.*, puis surchargées par la BDD.
  • Admin UI : toute nouvelle config doit être modifiable via l'interface admin.

Pattern : value = await config_service.get("perf.cache_ttl", settings.default_cache_ttl)

0 Glossaire des Acronymes

Acronyme Signification Description
TTFT Time To First Token Temps entre l'envoi de la requête et la réception du premier token de réponse. Indicateur clé de la réactivité perçue.
P50 / P95 Percentile 50 / 95 P50 = médiane (50% des requêtes sont plus rapides). P95 = 95% des requêtes sont plus rapides. Le P95 capture les cas lents.
RAG Retrieval-Augmented Generation Technique combinant recherche de documents (retrieval) et génération LLM pour des réponses contextualisées.
HNSW Hierarchical Navigable Small World Algorithme d'index vectoriel utilisé par ChromaDB pour la recherche de similarité rapide (ANN).
ANN Approximate Nearest Neighbors Recherche approximative des voisins les plus proches. Plus rapide que la recherche exacte, avec une légère perte de précision.
LRU Least Recently Used Stratégie de cache qui supprime en premier les éléments les moins récemment utilisés.
TTL Time To Live Durée de validité d'un élément en cache avant expiration automatique.
SSE Server-Sent Events Protocole HTTP permettant au serveur d'envoyer des données en continu vers le client (streaming unidirectionnel).
BM25 Best Matching 25 Algorithme de scoring textuel classique basé sur la fréquence des termes. Complémentaire à la recherche vectorielle.
RRF Reciprocal Rank Fusion Méthode pour fusionner les résultats de plusieurs systèmes de recherche (ex: dense + BM25).
Cross-encoder - Modèle qui prend en entrée (query, document) ensemble pour scorer la pertinence. Plus précis qu'un bi-encoder mais plus lent.

0.3 Préchargement des modèles au démarrage

Concept : Charger chat + embedding au démarrage pour éliminer la latence du premier appel.

Implémentation : Endpoint API qui lit les modèles depuis la BDD et les précharge.

# Endpoint backend (app/features/admin/config/router.py)
@router.post("/ollama/preload")
async def preload_ollama_models(
    db: AsyncSession = Depends(get_db),
    admin: User = Depends(get_current_admin_user)
):
    """Précharge les modèles Ollama configurés en BDD."""
    from app.features.system.service import SystemConfigService
    config_service = SystemConfigService(db)

    # Lire modèles depuis BDD
    chat_model = await config_service.get("llm.model", "mistral:latest")
    embed_model = await config_service.get("llm.embedding_model", "nomic-embed-text:latest")
    keep_alive = await config_service.get("llm.ollama.keep_alive", "24h")

    ollama_url = f"http://{settings.ollama_host}:{settings.ollama_port}"

    async with httpx.AsyncClient(timeout=120.0) as client:
        # Précharger chat
        await client.post(
            f"{ollama_url}/api/generate",
            json={"model": chat_model, "prompt": "hi", "keep_alive": keep_alive}
        )
        # Précharger embedding
        await client.post(
            f"{ollama_url}/api/embeddings",
            json={"model": embed_model, "prompt": "test", "keep_alive": keep_alive}
        )

    return {"status": "ok", "models_loaded": [chat_model, embed_model]}

            version = version_response.json().get("version", "unknown")

            server_status = {
                "status": "running",
                "version": version,
                "url": ollama_url,
                "loaded_models": [
                    {
                        "name": m["name"],
                        "size_gb": round(m["size"] / 1e9, 2),
                        "vram_gb": round(m.get("size_vram", 0) / 1e9, 2),
                        "using_gpu": m.get("size_vram", 0) > 0
                    }
                    for m in loaded_models
                ]
            }

        server_status = {"status": "error", "error": str(e)}

    return {
        "config": config,
        "server": server_status
    }

async def get_rag_config(db: Optional[AsyncSession] = None) -> RAGConfig:
    """
    Récupère la config RAG avec cache TTL.
    ⚠️ Le TTL est lui-même configurable en BDD (perf.rag_config_cache_ttl).
    """
    global _rag_config_cache

    now = time.time()
    cached_config, cached_time, cached_ttl = _rag_config_cache

    # Retourner le cache si valide (TTL non expiré)
    if cached_config and cached_ttl > 0 and (now - cached_time) < cached_ttl:
        logger.debug("RAG config from cache")
        return cached_config

    if db is None:
        return RAGConfig()  # Valeurs par défaut de settings

    # Charger depuis DB avec le TTL configurable
    from app.features.system.service import SystemConfigService
    config_service = SystemConfigService(db)

    # Le TTL du cache est lui-même en BDD !
    cache_ttl = float(await config_service.get(
        "perf.rag_config_cache_ttl",
        settings.default_rag_config_cache_ttl  # 30.0 par défaut
    ))

    config = RAGConfig(...)  # Charger les autres valeurs depuis DB
    _rag_config_cache = (config, now, cache_ttl)
    return config


def invalidate_rag_config_cache():

2.1 Embedding Parallèle avec Semaphore

Fichier : app/ingest_v2.py

async def generate_embeddings(
    self,
    texts: List[str],
    db: AsyncSession,  # Session pour accès config BDD
    progress_callback: Optional[Callable] = None,
    model: Optional[str] = None
) -> List[List[float]]:
    """
    Génère les embeddings en parallèle avec semaphore.
    ⚠️ Tous les paramètres proviennent de la BDD.
    """
    from app.features.system.service import SystemConfigService
    config_service = SystemConfigService(db)

    # Paramètres depuis la BDD
    batch_size = int(await config_service.get(
        "perf.embedding_batch_size", settings.default_embedding_batch_size  # 100
    ))
    max_concurrent = int(await config_service.get(
        "perf.embedding_max_concurrent", settings.default_embedding_max_concurrent  # 3
    ))

    semaphore = asyncio.Semaphore(max_concurrent)

    async def process_batch(batch_idx: int, batch: List[str]):
        async with semaphore:
            embeddings = await self._embed_batch(batch, model)
            return batch_idx, embeddings

    batches = [texts[i:i + batch_size] for i in range(0, len(texts), batch_size)]
    tasks = [process_batch(idx, batch) for idx, batch in enumerate(batches)]

    results = await asyncio.gather(*tasks)
    results.sort(key=lambda x: x[0])

    return [emb for _, embeddings in results for emb in embeddings]

# ⚠️ Clés BDD à créer :
#   - perf.embedding_batch_size (int, default: 100)
#   - perf.embedding_max_concurrent (int, default: 3)

Impact : 2-3x plus rapide pour gros documents (1000+ chunks)

3.1 Cache Résultats Retrieval (LRU + TTL)

Nouveau fichier : app/common/utils/query_cache.py

"""Cache LRU avec TTL pour résultats de recherche ChromaDB."""
import hashlib
import time
from dataclasses import dataclass
from typing import Any, Dict, Optional

from app.core.config import settings

@dataclass
class CacheEntry:
    value: Any
    timestamp: float

class QueryResultCache:
    """
    Cache query → chunk_ids pour les requêtes fréquentes.
    LRU = supprime les moins récemment utilisés quand plein.
    TTL = expire après N secondes (données peuvent changer).

    ⚠️ Les paramètres sont chargés depuis la BDD au démarrage
    et peuvent être rechargés dynamiquement.
    """
    def __init__(self):
        self._cache: Dict[str, CacheEntry] = {}
        # Valeurs par défaut depuis settings, surchargées par BDD
        self._maxsize = settings.default_query_cache_size  # 500
        self._ttl = settings.default_query_cache_ttl  # 300.0

    async def reload_config(self, db):
        """Recharge les paramètres depuis la BDD."""
        from app.features.system.service import SystemConfigService
        config_service = SystemConfigService(db)

        self._maxsize = int(await config_service.get(
            "perf.query_cache_size", settings.default_query_cache_size
        ))
        self._ttl = float(await config_service.get(
            "perf.query_cache_ttl", settings.default_query_cache_ttl
        ))

    def _make_key(self, query: str, corpus_id: str, provider: str) -> str:
        """
        Clé de cache inclut corpus_id et provider car :
        - Même query sur corpus différent → résultats différents
        - Même corpus mais provider différent → embeddings incompatibles
        """
        content = f"{query}:{corpus_id}:{provider}"
        return hashlib.md5(content.encode()).hexdigest()

    def get(self, query: str, corpus_id: str, provider: str) -> Optional[Any]:
        key = self._make_key(query, corpus_id, provider)
        entry = self._cache.get(key)
        if entry and (time.time() - entry.timestamp) < self._ttl:
            return entry.value
        return None

    def set(self, query: str, corpus_id: str, provider: str, value: Any):
        key = self._make_key(query, corpus_id, provider)
        if len(self._cache) >= self._maxsize:
            oldest = min(self._cache.items(), key=lambda x: x[1].timestamp)
            del self._cache[oldest[0]]
        self._cache[key] = CacheEntry(value=value, timestamp=time.time())

class PinnedDocsCache:
    """
    Cache des chunks les plus utilisés (FAQ, docs importants).
    IMPORTANT : Un cache par provider (embeddings incompatibles).

    ⚠️ Paramètres configurables en BDD.
    """

    def __init__(self):
        # Cache séparé par provider : {provider: {chunk_id: (text, embedding)}}
        self._pinned: Dict[str, Dict[str, Tuple[str, List[float]]]] = {
            "ollama": {},
            "llamacpp": {}
        }
        self._access_count: Dict[str, int] = {}
        # Valeurs par défaut, surchargées par BDD
        self._max_pinned = settings.default_pinned_cache_size  # 100
        self._pin_threshold = settings.default_pin_access_threshold  # 5

    async def reload_config(self, db):
        """Recharge les paramètres depuis la BDD."""
        from app.features.system.service import SystemConfigService
        config_service = SystemConfigService(db)

        self._max_pinned = int(await config_service.get(
            "perf.pinned_cache_size", settings.default_pinned_cache_size
        ))
        self._pin_threshold = int(await config_service.get(
            "perf.pin_access_threshold", settings.default_pin_access_threshold
        ))

    def record_access(self, chunk_id: str, text: str, embedding: List[float], provider: str):
        """Enregistre un accès et pin si fréquent."""
        self._access_count[chunk_id] = self._access_count.get(chunk_id, 0) + 1

        provider_cache = self._pinned.get(provider, {})
        if self._access_count[chunk_id] > self._pin_threshold and chunk_id not in provider_cache:
            if len(provider_cache) >= self._max_pinned:
                least = min(provider_cache.keys(), key=lambda k: self._access_count.get(k, 0))
                del provider_cache[least]
            provider_cache[chunk_id] = (text, embedding)

    def get_pinned(self, chunk_id: str, provider: str) -> Optional[Tuple[str, List[float]]]:
        return self._pinned.get(provider, {}).get(chunk_id)

4.2 Métriques P50/P95

Nouveau fichier : app/common/utils/metrics.py

"""Calcul de percentiles pour monitoring performances."""
import statistics
from collections import deque
from typing import Dict, List

class LatencyMetrics:
    """
    Collecte les latences et calcule P50/P95.
    P50 = médiane (50% des requêtes plus rapides)
    P95 = 95% des requêtes plus rapides (capture les outliers)
    """
    def __init__(self, window_size: int = 1000):
        self._windows: Dict[str, deque] = {}
        self._window_size = window_size

    def record(self, metric_name: str, value_ms: float):
        if metric_name not in self._windows:
            self._windows[metric_name] = deque(maxlen=self._window_size)
        self._windows[metric_name].append(value_ms)

    def get_percentiles(self, metric_name: str) -> Dict[str, float]:
        values = list(self._windows.get(metric_name, []))
        if len(values) < 10:
            return {"p50": 0, "p95": 0, "count": len(values)}

        sorted_values = sorted(values)
        p50_idx = int(len(sorted_values) * 0.50)
        p95_idx = int(len(sorted_values) * 0.95)

        return {
            "p50": sorted_values[p50_idx],
            "p95": sorted_values[p95_idx],
            "count": len(values),
            "mean": statistics.mean(values)
        }

    def get_summary(self) -> Dict[str, Dict]:
        return {name: self.get_percentiles(name) for name in self._windows}

# Singleton global
latency_metrics = LatencyMetrics()

5.1 Rerank avec Cross-Encoder

Concept : Après retrieval (top 20), re-scorer avec un modèle plus précis pour garder les 5-8 meilleurs.

Nouveau fichier : app/common/utils/rerank.py

"""
Reranking avec cross-encoder léger.
Cross-encoder : prend (query, document) ensemble → score de pertinence.
Plus précis qu'un bi-encoder (embedding séparé) mais plus lent.
"""
from typing import List, Tuple
import httpx

class LightweightReranker:
    """
    Rerank léger via Ollama ou modèle dédié.
    Appliqué sur top 20 → garde top 5-8.
    Latence cible : < 100ms (sinon désactiver).

    IMPORTANT - Respect du corpus :
    - Les chunks de corpus DIFFÉRENTS doivent être conservés même si similaires
      (contextes potentiellement différents)
    - La déduplication ne s'applique qu'au sein du MÊME corpus
    """

    def __init__(self, model: str = "nomic-embed-text:latest"):
        self._model = model
        self._enabled = True
        self._timeout = 100  # ms max

    async def rerank(
        self,
        query: str,
        documents: List[Tuple[str, float, dict]],  # (text, score, metadata)
        top_k: int = 5
    ) -> List[Tuple[str, float, dict]]:
        """
        Re-score les documents et retourne les top_k meilleurs.
        Metadata doit contenir : corpus_id, document_id, source_id
        """
        if not self._enabled or len(documents) <= top_k:
            return documents[:top_k]

        query_words = set(query.lower().split())
        scored = []

        for text, original_score, metadata in documents:
            doc_words = set(text.lower().split()[:100])
            overlap = len(query_words & doc_words) / max(len(query_words), 1)
            combined_score = original_score * 0.7 + overlap * 0.3
            scored.append((text, combined_score, metadata))

        scored.sort(key=lambda x: x[1], reverse=True)
        return scored[:top_k]

reranker = LightweightReranker()

6.2 Hybrid Search Dense + BM25

Concept : Combiner recherche vectorielle (dense) et recherche textuelle (BM25) avec fusion RRF.

"""
BM25 = algorithme de scoring textuel classique (TF-IDF amélioré).
Dense = recherche par embeddings vectoriels.
RRF = Reciprocal Rank Fusion (fusion des rankings).

Formule RRF : score = Σ 1/(k + rank_i) pour chaque système.
"""

def rrf_fusion(dense_results, bm25_results, k=60):
    """Fusionne les résultats de deux systèmes avec RRF."""
    scores = {}

    for rank, (doc_id, _) in enumerate(dense_results):
        scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank + 1)

    for rank, (doc_id, _) in enumerate(bm25_results):
        scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank + 1)

    # Trier par score RRF décroissant
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)
