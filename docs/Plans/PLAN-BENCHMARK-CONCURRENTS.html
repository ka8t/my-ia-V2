Points d'architecture différenciants MY-IA

  • Configuration 100% en BDD — Seuls les credentials PostgreSQL sont en .env. Tout le reste (LLM, RAG, storage, etc.) est modifiable via Admin UI sans redémarrage.
  • Support llama.cpp natif — Contrairement aux autres qui passent par Ollama, MY-IA supporte llama-server en direct pour exploiter GPU Metal/CUDA.
  • Architecture feature-based — Organisation en modules indépendants (features/chat, features/corpus, features/sources).
  • Frontend léger — Vanilla JS sans framework lourd, templates Handlebars, chargement rapide.

Positionnement MY-IA — Section 12

Proposition de valeur unique

🤖 MY-IA : "Plateforme RAG 100% souveraine"

MY-IA est une plateforme RAG enterprise-ready avec une philosophie claire :

  • Souveraineté totale — Aucun appel API cloud, aucune donnée externe, choix délibéré
  • Liberté des modèles — Tout modèle via Ollama (Mistral, Llama, Qwen...) ou GGUF (llama.cpp)
  • Multi-plateforme — macOS (Metal) + Linux (CPU, CUDA préparable) + VPS sans GPU
  • Sources Web avancées — DuckDuckGo, Google, Wikipedia + crawling multi-niveaux (MCP, BDD, API : préparés)
  • Multimédia — OCR images (pytesseract), Voice (Whisper + TTS, beta)
  • 150+ endpoints API — API REST complète, 16 modules backend
  • Configuration dynamique — 100% en BDD, modifiable via Admin UI sans redémarrage
  • Gestion documentaire — Versioning, corpus, collections, indexation TTL
  • Sécurité enterprise — JWT, RBAC, audit complet (OAuth préparé)

Philosophie du projet

🎯 Souveraineté par design — MY-IA ne fait et ne fera jamais d'appels à des API cloud (OpenAI, Anthropic, Google...). Ce n'est pas une fonctionnalité manquante, c'est le cœur de la proposition de valeur. Les données restent 100% sur l'infrastructure de l'utilisateur.

Architecture hybride (Docker + natif)

⚡ LLM en natif pour les performances GPU — Ollama et llama.cpp tournent en dehors de Docker pour accéder directement au GPU (Metal/CUDA). Les autres services (FastAPI, PostgreSQL, ChromaDB, Nginx) restent conteneurisés.
🐳 Dans Docker
  • FastAPI (backend)
  • PostgreSQL (BDD)
  • ChromaDB (vecteurs)
  • Nginx (reverse proxy)
🖥️ En natif (hors Docker)
  • Ollama (accès GPU direct)
  • llama.cpp / llama-server (GPU Metal/CUDA)
  • Communication via host.docker.internal

Plateformes supportées

🍎 macOS (Apple Silicon)
  • GPU Metal pour llama.cpp
  • Ollama natif avec Metal
  • Développement actuel sur Mac M1
🐧 Linux (serveurs / VPS)
  • Services Docker + LLM natif
  • CPU-only fonctionnel (plus lent)
  • CUDA activable si GPU NVIDIA
