Contexte et objectifs — Section 1

Problématique

Le provider LlamaCppProvider existe mais ne charge pas sa configuration depuis la BDD comme le fait OllamaProvider. Il utilise uniquement les valeurs par défaut de settings (variables d'environnement).

De plus, llama-server doit tourner en natif (pas dans Docker) pour bénéficier de l'accélération GPU Metal sur Mac Apple Silicon.

Objectifs

  • Charger config depuis BDD — avec cache TTL (comme Ollama)
  • Support multi-client — via --parallel
  • Restart automatique via API — endpoint pour redémarrer avec config BDD
  • Lecture config BDD au démarrage — option --from-db dans llamacpp.sh
  • Vérification sync config — comparer config BDD vs serveur running
  • Non-régression — ne pas casser l'existant Ollama

Contraintes

⚠️ Pas de Docker pour llama.cpp — llama-server doit tourner en natif sur l'hôte pour accéder au GPU Metal. La communication se fait via host.docker.internal:8085 depuis les containers Docker.

💡 Metal activé par défaut — Sur macOS Apple Silicon, Metal est automatiquement activé lors de la compilation. Aucun flag spécial n'est requis. 
# Créer le dossier de build

# Compilation parallèle (utilise tous les cœurs)
cmake --build . --config Release -j $(sysctl -n hw.ncpu)

# Durée : ~2-3 minutes sur M1 Pro

Étape 5 : Configuration optimale M1 Pro 32 Go

5.1 Commande de production recommandée

# Chemins
LLAMA_SERVER="/Users/mac/Documents/Code/llama.cpp/build/bin/llama-server"
MODEL="/Users/mac/Documents/Code/my-ia/models/gguf/gemma-2-9b-it-Q4_K_M.gguf"

# Configuration optimale pour M1 Pro 32 Go avec Gemma 9B
$LLAMA_SERVER \
    -m $MODEL \
    --host 0.0.0.0 \
    --port 8085 \
    -c 4096 \
    -b 2048 \
    -ngl 99 \
    -np 4 \
    -fa on \
    --embedding \
    --metrics

# Explication des options :
# -m                 : Chemin vers le modèle GGUF
# -c 4096            : 4K tokens de contexte par slot (alias: --ctx-size)
# -b 2048            : Batch size logique (alias: --batch-size)
# -ngl 99            : Toutes les couches sur GPU Metal (alias: --gpu-layers)
# -np 4              : 4 slots parallèles (alias: --parallel)
# -fa on             : Flash Attention activé (alias: --flash-attn)
# --embedding        : Active /v1/embeddings pour le RAG
# --metrics          : Active /metrics (Prometheus)

# Note : --cont-batching est activé PAR DÉFAUT depuis 2024
# Note : --webui est activé par défaut (UI web sur /)

5.2 Commande alternative avec téléchargement HuggingFace

# Démarrage direct sans téléchargement préalable
LLAMA_SERVER="/Users/mac/Documents/Code/llama.cpp/build/bin/llama-server"

$LLAMA_SERVER \
    -hf bartowski/gemma-2-9b-it-GGUF:Q4_K_M \
    --host 0.0.0.0 \
    --port 8085 \
    -c 4096 \
    -ngl 99 \
    -np 4 \
    -fa on \
    --embedding \
    --metrics

5.3 Estimation mémoire

# Formule approximative :
# Mémoire = Taille_modèle + (parallel × ctx_size × 2 Mo)
#
# Gemma 9B Q4 + 4 slots × 4096 ctx :
# ~5 Go + (4 × 4096 × 0.002 Go) ≈ 5 + 3.2 = ~8-10 Go
#
# Avec 32 Go RAM, il reste ~22 Go pour le système et autres apps

5.4 Utiliser le script MY-IA

# Le script llamacpp.sh gère tout automatiquement
./scripts/llamacpp.sh start --from-db

# Ou avec options manuelles
./scripts/llamacpp.sh start \
    --model models/gguf/gemma-2-9b-it-Q4_K_M.gguf \
    --embed

# Vérifier le statut
./scripts/llamacpp.sh status

# Voir les logs
./scripts/llamacpp.sh logs

async def get_llamacpp_config(db=None) -> LlamaCppConfig:
    """Récupère la config llama.cpp depuis BDD avec cache TTL."""
    global _llamacpp_config_cache

    now = time.time()
    cached_config, cached_time, ttl = _llamacpp_config_cache

    if cached_config and ttl > 0 and (now - cached_time) < ttl:
        return cached_config

    if db is None:
        return LlamaCppConfig()

    try:
        from app.features.system.service import SystemConfigService
        config_service = SystemConfigService(db)

        config = LlamaCppConfig(
            host=str(await config_service.get("llm.llamacpp.host", "host.docker.internal")),
            port=int(await config_service.get("llm.llamacpp.port", 8085)),
            ctx_size=int(await config_service.get("llm.llamacpp.ctx_size", 4096)),
            # ... autres champs ...
        )

        _llamacpp_config_cache = (config, now, 30.0)
        return config
    except Exception as e:
        logger.warning(f"[llama.cpp] Failed to load config from DB: {e}")
        return LlamaCppConfig()

def invalidate_llamacpp_config_cache():
    """Invalide le cache config llama.cpp."""
    global _llamacpp_config_cache
    _llamacpp_config_cache = (None, 0, 30.0)
    logger.debug("[llama.cpp] Config cache invalidated")

@staticmethod
async def restart_llamacpp_server(db: AsyncSession) -> dict:
    """Redémarre llama-server avec les paramètres depuis la BDD."""
    import asyncio
    from pathlib import Path

    script_path = Path(__file__).parents[4] / "scripts" / "llamacpp.sh"

    try:
        process = await asyncio.create_subprocess_exec(
            str(script_path), "restart", "--from-db",
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE
        )
        stdout, stderr = await asyncio.wait_for(
            process.communicate(),
            timeout=60.0
        )

        if process.returncode == 0:
            from app.common.llm import invalidate_llamacpp_config_cache
            invalidate_llamacpp_config_cache()

            return {
                "success": True,
                "message": "llama-server restarted successfully",
                "status": "running"
            }
        else:
            return {
                "success": False,
                "message": f"Restart failed: {stderr.decode()}",
                "status": "error"
            }
    except asyncio.TimeoutError:
        return {"success": False, "message": "Restart timeout (60s)", "status": "timeout"}

📦 Service compare_llamacpp_configs()
@staticmethod
async def compare_llamacpp_configs(db: AsyncSession) -> dict:
    """Compare la configuration BDD avec celle du serveur en cours."""
    from app.common.llm import get_llamacpp_config

    db_config = await get_llamacpp_config(db)
    running_config = await ConfigService.get_llamacpp_running_config()

    if not running_config:
        return {"in_sync": None, "server_running": False, "restart_required": False}

    differences = []
    critical_keys = ["ctx_size", "gpu_layers", "parallel", "batch_size", "embedding_mode"]

    for key in critical_keys:
        db_val = getattr(db_config, key, None)
        run_val = running_config.get(key)
        if db_val == -1:
            continue  # Auto = pas de vérification
        if run_val is not None and db_val != run_val:
            differences.append({"key": key, "db_value": db_val, "running_value": run_val})

    return {
        "in_sync": len(differences) == 0,
        "differences": differences,
        "restart_required": len(differences) > 0,
        "server_running": True
    }

#!/bin/bash
# Helper pour lecture configuration depuis BDD

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_ROOT="$(dirname "$(dirname "$SCRIPT_DIR")")"

# Charge les variables depuis .env
if [[ -f "$PROJECT_ROOT/.env" ]]; then
    set -a
    source "$PROJECT_ROOT/.env"
    set +a
fi

DB_CONTAINER="${SANITIZED_PREFIX:-my_ia}_postgres"
DB_USER="${APP_DB_USER:-my_ia_db_user}"
DB_NAME="${APP_DB_NAME:-my_ia_db}"

get_db_config() {
    local key="$1"
    local default="$2"

    if ! docker ps --format '{{.Names}}' | grep -q "^${DB_CONTAINER}$"; then
        echo "$default"
        return
    fi

    local result
    result=$(docker exec "$DB_CONTAINER" psql \
        -U "$DB_USER" -d "$DB_NAME" -t -A \
        -c "SELECT value FROM system_configs WHERE key='$key'" \
        2>/dev/null | tr -d '[:space:]')

    if [[ -n "$result" ]]; then
        echo "$result"
    else
        echo "$default"
    fi
}

get_db_config_bool() {
    local key="$1"
    local default="$2"
    local value=$(get_db_config "$key" "$default")

    case "${value,,}" in
        true|1|yes|on) echo "true" ;;
        *) echo "false" ;;
    esac
}

# Fonction pour charger les chemins depuis la BDD
load_paths_from_db() {
    source "$SCRIPT_DIR/lib/db-config.sh"

    local db_server_path=$(db_config_get "llm.llamacpp.server_path" "")
    local db_models_dir=$(db_config_get "llm.llamacpp.models_dir" "")

    if [[ -n "$db_server_path" ]]; then
        LLAMACPP_BIN="$db_server_path"
        log_info "Chemin llama-server depuis BDD: $LLAMACPP_BIN"
    fi
    if [[ -n "$db_models_dir" ]]; then
        MODELS_DIR="$db_models_dir"
        log_info "Répertoire modèles depuis BDD: $MODELS_DIR"
    fi
}
