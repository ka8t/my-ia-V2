Trajectoire proposée — Sprints

Sprint 1 (S1) — P0 complet (5 actions) 3-5 jours. Focus : restaurer fonctionnalité critique (édition user, ingestion xlsx) + tests régression + smoke E2E user.
Sprint 2-3 (S2-S3) — P1 (8 actions) 10-14 jours. Focus : restaurer composants UI manquants (progress.js, reindex-banner, bulk actions bar), boucher les fonctionnalités admin manquantes, lancer la couverture tests des 5 zones critiques.
Sprint 4-5 (S4-S5) — P2 partiel (complétion features) 15-20 jours. Focus : modes édition, geo toggle, RAG overrides, admin documents.
Sprint 6+ (continu) — P2.7 + P3 20-40 jours. Recouvrement tests, migration /api/v1/, suite E2E complète. En parallèle des développements feature.

Critères d'acceptation de clôture

  • Tous les items P0 sont livrés, testés, et déployés
  • Au moins 6/8 items P1 sont livrés
  • Couverture tests V2 atteint ≥ 60% des cases V1 (~1000 cases) sur les modules critiques
  • Aucun bug user-visible majeur détecté pendant 1 semaine de QA active
