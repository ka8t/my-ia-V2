Section 1

Contexte et objectif

↑ Sommaire

Problème actuel

Un document ne peut appartenir qu'à un seul corpus (relation 1 à 1 via Document.corpus_id).

Les sources externes peuvent déjà appartenir à plusieurs corpus (relation N à N via CorpusSource).

Objectif

  • Permettre à un document d'appartenir à plusieurs corpus
  • Uniformiser le modèle entre documents et sources
  • Faciliter la réutilisation du contenu entre corpus thématiques

Règle d'unicité

⚠️
Règle obligatoire
Un même élément (document, source ou collection) ne peut être ajouté qu'une seule fois à un corpus donné. Toute tentative d'ajout en double retourne une erreur HTTP 409 Conflict.
Table pivotContrainte uniqueMessage d'erreur
corpus_documents uq_corpus_document(corpus_id, document_id) "Document deja dans ce corpus"
corpus_sources uq_corpus_source(corpus_id, source_id) "Source deja dans ce corpus"
corpus_collections uq_corpus_collection(corpus_id, collection_id) "Collection deja dans ce corpus"

Cas d'usage

💡
Exemple : Un document "Guide API Remotion" peut être pertinent pour :
  • Corpus "Documentation Technique"
  • Corpus "Tutoriels Vidéo"
  • Corpus "Références API"

Nouvelle table : corpus_documents

CREATE TABLE corpus_documents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    corpus_id UUID NOT NULL REFERENCES corpus(id) ON DELETE CASCADE,
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    priority INTEGER DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW(),

    UNIQUE(corpus_id, document_id)
);

CREATE INDEX idx_corpus_documents_corpus ON corpus_documents(corpus_id);
CREATE INDEX idx_corpus_documents_document ON corpus_documents(document_id);

Modèle SQLAlchemy

class CorpusDocument(Base):
    """Table de liaison entre Corpus et Documents."""
    __tablename__ = "corpus_documents"
    __table_args__ = (
        UniqueConstraint('corpus_id', 'document_id', name='uq_corpus_document'),
    )

    id: Mapped[uuid.UUID] = mapped_column(primary_key=True, default=uuid.uuid4)
    corpus_id: Mapped[uuid.UUID] = mapped_column(
        ForeignKey("corpus.id", ondelete="CASCADE"), nullable=False, index=True
    )
    document_id: Mapped[uuid.UUID] = mapped_column(
        ForeignKey("documents.id", ondelete="CASCADE"), nullable=False, index=True
    )
    priority: Mapped[int] = mapped_column(default=0)
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())

    # Relations
    corpus: Mapped["Corpus"] = relationship(back_populates="corpus_documents")
    document: Mapped["Document"] = relationship(back_populates="corpus_memberships")

Modifications sur Document

class Document(Base):
    # SUPPRIMER : corpus_id (FK directe)
    # corpus_id: Mapped[Optional[uuid.UUID]] = ...  # À SUPPRIMER

    # GARDER : collection_id pour les documents privés
    collection_id: Mapped[Optional[uuid.UUID]] = mapped_column(...)

    # AJOUTER : relation N à N via table pivot
    corpus_memberships: Mapped[List["CorpusDocument"]] = relationship(
        back_populates="document",
        cascade="all, delete-orphan"
    )

    # Helper property pour accès direct aux corpus
    @property
    def corpus_list(self) -> List["Corpus"]:
        return [cm.corpus for cm in self.corpus_memberships]

Script de migration Alembic

# app/alembic/versions/xxx_corpus_documents_many_to_many.py

def upgrade():
    # 1. Créer la nouvelle table corpus_documents
    op.create_table(
        'corpus_documents',
        sa.Column('id', postgresql.UUID(as_uuid=True), primary_key=True),
        sa.Column('corpus_id', postgresql.UUID(as_uuid=True), nullable=False),
        sa.Column('document_id', postgresql.UUID(as_uuid=True), nullable=False),
        sa.Column('priority', sa.Integer(), default=0),
        sa.Column('created_at', sa.DateTime(timezone=True), server_default=sa.func.now()),
        sa.ForeignKeyConstraint(['corpus_id'], ['corpus.id'], ondelete='CASCADE'),
        sa.ForeignKeyConstraint(['document_id'], ['documents.id'], ondelete='CASCADE'),
        sa.UniqueConstraint('corpus_id', 'document_id', name='uq_corpus_document')
    )

    # 2. Migrer les données existantes
    op.execute("""
        INSERT INTO corpus_documents (id, corpus_id, document_id, priority, created_at)
        SELECT gen_random_uuid(), corpus_id, id, 0, NOW()
        FROM documents WHERE corpus_id IS NOT NULL
    """)

    # 3. Supprimer la contrainte existante
    op.drop_constraint('ck_document_corpus_or_collection', 'documents')

    # 4. Supprimer la colonne corpus_id
    op.drop_column('documents', 'corpus_id')

Bug corrigé : recherche RAG ignorait le filtrage corpus

🐛
Bug critique (2026-02-21)
La recherche RAG retournait des documents d'autres corpus non liés.
  • Symptôme : Chat avec collection "Remotion Ollama" affichait "windows-ami-reference.pdf" (document EC2)
  • Cause : get_corpus_collection_names() utilisait la FK directe Collection.corpus_id au lieu de la table pivot corpus_collections
  • Impact : Les collections partageant le même corpus_id direct étaient fusionnées, ignorant la relation N-to-N correcte
Correction : Mise à jour des deux fonctions pour utiliser CorpusCollection (table pivot).
Fichier modifiéChangement

app/features/chat/service.py _get_collection_corpus_id() : recherche via CorpusCollection au lieu de Collection.corpus_id

Bug corrigé : conflit de routage FastAPI sur les routes bulk

🐛
Bug critique (2026-02-22)
Les opérations bulk de suppression de sources et documents échouaient avec une erreur 422.
  • Symptôme : "Retirer la sélection" sur les sources dans la modale corpus retournait uuid_parsing error: invalid character
  • Cause : Dans FastAPI, les routes avec paramètres dynamiques (/{source_id}) capturaient les routes statiques (/bulk) si elles étaient définies AVANT dans le fichier
  • Impact : DELETE /corpus/{id}/sources/bulk → interprété comme DELETE /corpus/{id}/sources/{source_id="bulk"}
Correction : Réorganisation des routes pour placer /bulk AVANT /{source_id} et /{document_id}.
Fichier modifiéChangement
app/features/admin/corpus/router.py Routes /sources/bulk déplacées AVANT /sources/{source_id}
app/features/admin/corpus/router.py Routes /documents/bulk déplacées AVANT /documents/{document_id}
💡
Règle FastAPI
Les routes statiques (/bulk, /available) doivent toujours être définies AVANT les routes avec paramètres dynamiques (/{id}) pour éviter les conflits de routage.
