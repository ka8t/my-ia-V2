Pourquoi des modèles personnalisés ? — Section 1

⬆ Sommaire

Limites des modèles génériques

❌ Vocabulaire générique
Les modèles standards ne connaissent pas votre jargon métier, acronymes internes, ou terminologie spécifique.
❌ Style de réponse
Ton trop formel/informel, réponses trop longues/courtes, format non adapté à vos besoins.
❌ Connaissances manquantes
Le modèle ne connaît pas vos produits, processus, ou informations internes.

Avantages des modèles personnalisés

AspectModèle génériqueModèle personnalisé
Vocabulaire métier❌ Inconnu✅ Intégré
Style de réponse❌ Générique✅ Adapté
Précision métier❌ Variable✅ Optimisée
Taille modèleGrande (7B+)Optimisée (2-7B)
LatenceVariableRéduite
💡 Cas d'usage idéal : Un modèle 3B fine-tuné sur votre domaine peut surpasser un modèle 7B générique pour vos tâches spécifiques.

Types de personnalisation — Section 2

⬆ Sommaire
NIVEAUX DE PERSONNALISATION (du plus simple au plus complexe) ┌─────────────────────────────────────────────────────────────────┐ │ Niveau 1 : System Prompt │ │ Effort: ⭐ GPU: Non Temps: Minutes │ │ Personnalisation du comportement via instructions textuelles │ │ → Déjà implémenté dans MY-IA (Admin > LLM > System Prompt) │ └─────────────────────────────────────────────────────────────────┘ ▾ ┌─────────────────────────────────────────────────────────────────┐ │ Niveau 2 : RAG (Retrieval-Augmented Generation) │ │ Effort: ⭐⭐ GPU: Non Temps: Heures │ │ Injection de contexte depuis vos documents │ │ → Déjà implémenté dans MY-IA (Corpus, Documents, Sources) │ └─────────────────────────────────────────────────────────────────┘ ▾ ┌─────────────────────────────────────────────────────────────────┐ │ Niveau 3 : Fine-tuning LoRA/QLoRA │ │ Effort: ⭐⭐⭐ GPU: 8-24GB Temps: Heures-Jours │ │ Entraînement d'un adaptateur léger sur vos données │ │ → CE PLAN : À implémenter │ └─────────────────────────────────────────────────────────────────┘ ▾ ┌─────────────────────────────────────────────────────────────────┐ │ Niveau 4 : Full Fine-tuning │ │ Effort: ⭐⭐⭐⭐⭐ GPU: 48GB+ Temps: Jours-Semaines │ │ Réentraînement complet du modèle │ │ → Rarement nécessaire, très coûteux │ └─────────────────────────────────────────────────────────────────┘

Focus : Fine-tuning LoRA/QLoRA

LoRA (Low-Rank Adaptation) permet d'entraîner un petit « adaptateur » au lieu de modifier tout le modèle :

MéthodeVRAM requiseParamètres entraînésQualité
Full Fine-tuning48-80 GB100%Maximale
LoRA16-24 GB~1-5%Excellente
QLoRA8-16 GB~1-5%Très bonne
✅ Recommandation : QLoRA offre le meilleur rapport qualité/ressources pour un usage local sur Mac M1/M2/M3 ou GPU consumer.

Script d'export depuis MY-IA

# scripts/export_training_data.py

import json
from sqlalchemy import select
from app.models import ChatMessage, Conversation

async def export_conversations_to_alpaca(output_path: str):
    """
    Exporte les conversations MY-IA en format Alpaca.
    """
    async with async_session() as db:
        # Récupérer les conversations avec feedback positif
        result = await db.execute(
            select(ChatMessage)
            .where(ChatMessage.feedback_score >= 4)  # Bons feedbacks
            .order_by(ChatMessage.created_at)
        )
        messages = result.scalars().all()

        training_data = []
        for i in range(0, len(messages) - 1, 2):
            if messages[i].role == "user" and messages[i+1].role == "assistant":
                training_data.append({
                    "instruction": messages[i].content,
                    "input": "",
                    "output": messages[i+1].content
                })

        with open(output_path, "w", encoding="utf-8") as f:
            json.dump(training_data, f, ensure_ascii=False, indent=2)

        print(f"Exporté {len(training_data)} exemples vers {output_path}")

Exemple avec Unsloth

# train_custom_model.py
from unsloth import FastLanguageModel
from datasets import load_dataset
from trl import SFTTrainer
from transformers import TrainingArguments

# 1. Charger le modèle de base
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/mistral-7b-v0.3-bnb-4bit",
    max_seq_length=2048,
    load_in_4bit=True,  # QLoRA
)

# 2. Ajouter LoRA
model = FastLanguageModel.get_peft_model(
    model,
    r=16,              # Rank
    lora_alpha=32,
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
)

# 3. Charger les données
dataset = load_dataset("json", data_files="training_data.json")

# 4. Entraîner
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset["train"],
    dataset_text_field="text",
    max_seq_length=2048,
    args=TrainingArguments(
        per_device_train_batch_size=4,
        gradient_accumulation_steps=4,
        num_train_epochs=3,
        learning_rate=2e-4,
        output_dir="./output",
        logging_steps=10,
        save_steps=100,
    ),
)

trainer.train()

# 5. Sauvegarder en GGUF
model.save_pretrained_gguf(
    "my-custom-model",
    tokenizer,
    quantization_method="q4_k_m"
)

Exemple avec MLX (Mac)

# Sur Mac M1/M2/M3
pip install mlx-lm

# Fine-tuning LoRA
python -m mlx_lm.lora \
  --model mistralai/Mistral-7B-v0.3 \
  --data training_data.json \
  --train \
  --iters 1000 \
  --batch-size 4 \
  --lora-layers 16

# Fusion et conversion GGUF
python -m mlx_lm.fuse \
  --model mistralai/Mistral-7B-v0.3 \
  --adapter-path adapters \
  --save-path my-custom-model

python -m mlx_lm.convert \
  --model my-custom-model \
  --quantize q4_k_m \
  --output my-custom-model.gguf

API Backend pour l'entraînement

# app/features/admin/training/router.py

@router.post("/training/start")
async def start_training(
    request: TrainingRequest,
    background_tasks: BackgroundTasks,
    admin: User = Depends(get_current_admin_user)
):
    """Lance l'entraînement en arrière-plan."""
    job_id = str(uuid4())

    background_tasks.add_task(
        run_training_job,
        job_id=job_id,
        config=request.config,
        dataset_path=request.dataset_path
    )

    return {"job_id": job_id, "status": "started"}


@router.get("/training/{job_id}/status")
async def get_training_status(job_id: str):
    """Récupère la progression de l'entraînement."""
    status = TrainingJobManager.get_status(job_id)
    return {
        "job_id": job_id,
        "status": status.status,  # "running", "completed", "failed"
        "progress": status.progress,  # 0-100
        "current_epoch": status.current_epoch,
        "current_step": status.current_step,
        "loss": status.loss,
        "val_loss": status.val_loss,
        "eta_seconds": status.eta_seconds
    }
