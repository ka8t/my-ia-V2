Préparation du serveur — Section 2

Mise à jour du système

# Ubuntu / Debian
sudo apt update && sudo apt upgrade -y

# RHEL / Rocky Linux
sudo dnf update -y

Installation de Docker

1. Installer Docker Engine
Script officiel recommandé
2. Ajouter l'utilisateur au groupe docker
Permet d'exécuter docker sans sudo
3. Déconnecter / Reconnecter
Pour appliquer les changements de groupe
4. Vérifier l'installation
Tester avec docker run hello-world
# Installation Docker (script officiel)
curl -fsSL https://get.docker.com | sh

# Ajouter l'utilisateur actuel au groupe docker
sudo usermod -aG docker $USER

# Déconnexion nécessaire pour appliquer
exit

# Après reconnexion, vérifier
docker run hello-world

Installation GPU NVIDIA (Optionnel)

Si vous disposez d'un GPU NVIDIA :

# Installer les drivers NVIDIA
sudo apt install nvidia-driver-535

# Installer NVIDIA Container Toolkit
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
  sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
  sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt update && sudo apt install -y nvidia-container-toolkit

# Redémarrer Docker
sudo systemctl restart docker

# Vérifier
docker run --rm --gpus all nvidia/cuda:12.0-base nvidia-smi
⚠️ Redémarrage requis : Après l'installation des drivers NVIDIA, un redémarrage complet du serveur est recommandé.

Installation MY-IA — Section 3

Étape 1 : Télécharger MY-IA

# Cloner le projet
git clone https://github.com/votre-org/my-ia.git /opt/my-ia
cd /opt/my-ia

Étape 2 : Configurer l'environnement

# Copier le fichier de configuration
cp env.template .env

# Éditer la configuration
nano .env

Paramètres essentiels à configurer dans .env :

VariableDescriptionExemple
APP_NAME_PREFIX Préfixe pour les containers (sans espaces) my_ia
ADMIN_EMAIL Email du premier administrateur admin@entreprise.com
ADMIN_PASSWORD Mot de passe admin (généré si vide) MotDePasseSecurise123!
DEPLOY_ENV Environnement de déploiement prod ou dev
⚠️ Sécurité : Utilisez un mot de passe fort (min. 12 caractères, majuscules, chiffres, symboles). Changez les mots de passe par défaut immédiatement.

Étape 3 : Démarrer l'application

# Lancer l'installation et le démarrage
./scripts/start.sh

Le script effectue automatiquement :

  • Génération des clés — SECRET_KEY, JWT_SECRET si non définis
  • Téléchargement des images — PostgreSQL, ChromaDB, Nginx
  • Construction des containers — Application Python, interfaces web
  • Création de la base — Tables, utilisateur admin, données initiales
  • Démarrage des services — Tous les containers en séquence
✅ Installation terminée ! Accédez à https://votre-serveur:3000 (utilisateurs) et https://votre-serveur:8081 (administration).

Étape 4 : Configurer le modèle IA

MY-IA nécessite un modèle de langage. Deux options :

📦 Option A : Ollama (Recommandé)

# Le container Ollama démarre avec MY-IA
# Télécharger un modèle
docker exec my_ia_ollama ollama pull mistral

# Vérifier
docker exec my_ia_ollama ollama list

⚙️ Option B : llama.cpp

# Télécharger un modèle GGUF
wget https://huggingface.co/.../model.gguf

# Démarrer le serveur
./llama-server -m model.gguf \
  --embedding --port 8080

Ensuite, configurez le modèle dans l'interface admin : Configuration > Modèle IA.

Mise à jour — Section 5

Pour mettre à jour MY-IA vers une nouvelle version :

Procédure standard

# 1. Sauvegarder (obligatoire avant toute mise à jour)
./scripts/backup.sh

# 2. Arrêter l'application
./scripts/stop.sh

# 3. Récupérer la nouvelle version
git pull origin main

# 4. Redémarrer (reconstruction automatique si nécessaire)
./scripts/start.sh

# 5. Vérifier
curl -k https://localhost:8080/health
✅ Données préservées : Les documents, utilisateurs et conversations sont stockés dans des volumes Docker persistants. Ils ne sont pas affectés par les mises à jour.

Mise à jour avec migration

Si la mise à jour inclut des changements de base de données :

# Les migrations sont appliquées automatiquement au démarrage
# Vérifier les logs en cas de problème
docker compose logs -f app

Rollback

En cas de problème après une mise à jour :

# Arrêter
./scripts/stop.sh

# Revenir à la version précédente
git checkout v1.2.3  # ou le tag de la version précédente

# Redémarrer
./scripts/start.sh

# Restaurer la sauvegarde si nécessaire
./scripts/restore.sh backup-YYYYMMDD.tar.gz

Problèmes courants — Section 6

Les containers ne démarrent pas

# Voir les logs détaillés
docker compose logs -f app

# Causes fréquentes :
# - Port déjà utilisé : modifier les ports dans .env
# - Mémoire insuffisante : vérifier avec 'free -h'
# - Permissions : vérifier que l'utilisateur est dans le groupe docker

Erreur "Port already in use"

PortService concernéSolution
3000UI FrontendModifier UI_FRONT_PORT dans .env
8081UI AdminModifier UI_BACK_PORT dans .env
8080APIModifier APP_PORT dans .env
5432PostgreSQLArrêter le PostgreSQL local

Erreur de connexion base de données

# Vérifier que PostgreSQL fonctionne
docker compose logs postgres

# Redémarrer PostgreSQL
docker compose restart postgres

# Attendre 10 secondes puis redémarrer l'app
docker compose restart app

Le modèle IA ne répond pas

# Vérifier Ollama
docker compose logs ollama

# Vérifier qu'un modèle est installé
docker exec my_ia_ollama ollama list

# Si aucun modèle, en télécharger un
docker exec my_ia_ollama ollama pull mistral

Certificat SSL invalide

Par défaut, MY-IA utilise un certificat auto-signé. Pour la production :

# Installer certbot
sudo apt install certbot

# Générer un certificat Let's Encrypt
sudo certbot certonly --standalone -d myia.entreprise.com

# Copier les certificats
sudo cp /etc/letsencrypt/live/myia.entreprise.com/fullchain.pem ssl/
sudo cp /etc/letsencrypt/live/myia.entreprise.com/privkey.pem ssl/

# Redémarrer
docker compose restart ui-front ui-back
