Gestion des utilisateurs — Section 1

Accédez à la liste des utilisateurs via le menu Utilisateurs.

Créer un utilisateur

1. Cliquer sur "+ Nouveau"
Ouvre le formulaire de création
2. Remplir les informations
Email (identifiant), nom, prénom
3. Choisir le rôle
Utilisateur standard ou Administrateur
4. Envoyer l'invitation
Un email avec le lien d'activation est envoyé

Rôles et permissions

RôlePermissionsAccès
Utilisateur Chat, documents personnels, préférences Interface utilisateur uniquement
Administrateur Toutes les permissions utilisateur + gestion complète Interface utilisateur + Backoffice admin

Actions sur un utilisateur

ActionDescriptionQuand l'utiliser
✏️ Modifier Changer nom, email, rôle Mise à jour des informations
🔑 Réinitialiser mot de passe Envoie un email de réinitialisation Utilisateur qui a oublié son mot de passe
🚫 Désactiver Bloque l'accès sans supprimer les données Départ temporaire, congé longue durée
✅ Réactiver Restaure l'accès d'un compte désactivé Retour de l'utilisateur
🗑️ Supprimer Supprime le compte et toutes ses données Départ définitif (irréversible)

Voir l'activité d'un utilisateur

Cliquez sur un utilisateur pour voir ses détails :

📊 Statistiques
Nombre de messages, conversations, documents
📄 Documents
Liste des documents uploadés par l'utilisateur
💬 Conversations
Historique des conversations (accès support)
⚙️ Préférences
Paramètres personnalisés de l'utilisateur
⚠️ Respect de la vie privée : N'accédez aux conversations et documents utilisateurs que si nécessaire (support, audit de sécurité). Documentez vos accès.

Gestion des documents — Section 2

Documents système

Les documents système sont les documents officiels accessibles à tous les utilisateurs.

1. Accéder aux documents
Documents > Système ou cliquer sur une collection
2. Ajouter des documents
Glissez-déposez ou cliquez sur "+ Ajouter"
3. Attendre l'indexation
MY-IA analyse et indexe le contenu
4. Vérifier
Testez une question pour confirmer l'indexation

Opérations sur les documents

OpérationDescriptionImpact
👁️ Voir Aperçu du document dans le navigateur Aucun
⬇️ Télécharger Récupérer le fichier original Aucun
🔄 Réindexer Reconstruire l'index du document Recherche indisponible pendant l'opération
📋 Déplacer Changer de collection Peut affecter les modes associés
🗑️ Supprimer Retirer le document et son index Irréversible, supprime aussi les références

État des documents

Chaque document a un statut d'indexation :

  • Indexé — Document prêt, utilisable dans les recherches
  • En cours — Indexation en cours, patientez
  • Erreur — Problème lors de l'indexation (format, contenu)
  • En attente — Dans la file d'attente d'indexation

Documents des utilisateurs

Vous pouvez consulter les documents de chaque utilisateur :

  • Utilisateurs > [Utilisateur] > Documents
  • Voir la liste, l'espace utilisé, le quota restant
  • Possibilité de supprimer des documents (cas exceptionnels)

Sources externes — Section 3

MY-IA peut se connecter à des sources de données externes pour enrichir ses réponses.

Types de sources

🌐 Sites web
Indexez le contenu de sites internet. Utile pour la documentation en ligne, les bases de connaissances publiques.
🔗 APIs REST
Connectez des APIs pour des données en temps réel. CRM, ERP, bases de données métier.
🗄️ Bases SQL
Interrogez directement vos bases de données relationnelles.

Ajouter une source web

1. Créer la source
Sources > + Nouvelle source > Site web
2. Configurer l'URL
URL de départ du crawl
3. Paramétrer le crawl
Profondeur, filtres d'URL, fréquence
4. Lancer l'indexation
Cliquez sur "Indexer maintenant"
5. Associer à une collection
Pour l'intégrer aux recherches

Paramètres de crawl

ParamètreDescriptionRecommandé
Profondeur Nombre de niveaux de liens à suivre 2-3 (au-delà, très long)
Filtre d'URL Pattern pour inclure/exclure des pages Ex: /docs/* pour n'indexer que la doc
Fréquence Réindexation automatique Hebdomadaire pour sites actifs
Délai entre requêtes Temps entre chaque page crawlée 500ms (respecter le serveur)
⚠️ Respect des sites : Vérifiez que vous avez le droit d'indexer le site (robots.txt, conditions d'utilisation). Évitez de surcharger les serveurs avec des crawls trop agressifs.

Logs d'audit — Section 5

MY-IA enregistre toutes les actions importantes pour la traçabilité et la conformité.

Actions auditées

CatégorieActionsDétails enregistrés
Authentification Connexion, déconnexion, échec Utilisateur, date, IP, navigateur
Utilisateurs Création, modification, suppression Qui a fait quoi, anciennes/nouvelles valeurs
Documents Upload, suppression, déplacement Fichier, utilisateur, collection
Configuration Changement de paramètre Paramètre, ancienne/nouvelle valeur
Sécurité Changement de rôle, blocage compte Détails de l'action

Consulter les logs

Accédez aux logs via Système > Logs d'audit :

  • Filtrer par type — Auth, utilisateurs, documents, config
  • Filtrer par utilisateur — Voir les actions d'une personne
  • Filtrer par date — Période spécifique
  • Rechercher — Par mot-clé dans les détails

Conservation des logs

  • Durée de rétention — Configurable (par défaut 1 an)
  • Export — Téléchargez les logs en CSV pour archivage
  • Conformité — Adaptez la rétention selon vos obligations légales (RGPD)

Maintenance — Section 6

Sauvegardes

MY-IA stocke ses données dans des volumes Docker. Pour sauvegarder :

# Sauvegarde complète (base + documents + config)
./scripts/backup.sh

# Le fichier est créé dans backups/
ls -la backups/
✅ Sauvegarde automatique : Configurez une tâche cron pour sauvegarder quotidiennement :
0 2 * * * /opt/my-ia/scripts/backup.sh

Restauration

# Restaurer une sauvegarde
./scripts/restore.sh backups/backup-20260212.tar.gz
🚨 Attention : La restauration écrase les données actuelles. Faites une sauvegarde avant de restaurer si vous n'êtes pas sûr.

Redémarrage des services

# Redémarrer tous les services
docker compose restart

# Redémarrer un service spécifique
docker compose restart app
docker compose restart postgres
docker compose restart ollama

Nettoyage

# Voir l'espace utilisé par Docker
docker system df

# Nettoyer les données temporaires (images non utilisées, cache)
docker system prune

# Nettoyer les logs volumineux
docker compose logs --tail 1000 > logs.txt
truncate -s 0 /var/lib/docker/containers/*/*-json.log
